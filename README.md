# Генератор КТП (календарно-тематическое планирование)

Проставляет даты занятий в плане `.doc` (Word 97-2003) по учебному календарю
часов `.xlsx` (праздники помечены красным — они пропускаются).

## Установка

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt   # openpyxl, olefile (+Flask для веб-интерфейса)
```

## Запуск

### Веб-GUI (рекомендуется)

```bash
python gui.py                 # откройте http://127.0.0.1:5000 в браузере
python gui.py --port 8080     # другой порт
python gui.py --host 0.0.0.0  # доступ с других компьютеров в сети
```

Что умеет интерфейс:

1. Перетаскивание (или выбор) файла плана `.doc` и календаря `.xlsx` — сразу
   показывает, сколько занятий распознано и сколько рабочих дат/праздников в
   календаре.
2. Кнопки-чипы дней недели (можно выбрать несколько) + дата начала занятий +
   имя итогового файла.
3. **Предпросмотр дат** — таблица «№ / Тема / Было / Стало / День недели» без
   создания файла; предупреждает, если рабочих дат не хватает.
4. **Сгенерировать и скачать** — сохраняет `output/<имя>.doc`, делает
   самопроверку (перечитывание результата) и даёт ссылку на скачивание.

Работает полностью локально, без интернета. GUI и CLI используют общую логику
(`ktpgen/pipeline.py`), поэтому результаты идентичны.

### CLI

**Запускать нужно корневой скрипт `run.py`, а не модули из `ktpgen/`.**

Модули пакета (`ktpgen/scheduler.py` и др.) содержат относительные импорты
(`from .calendar_parser import ...`), поэтому команда вида

```bash
python ktpgen/scheduler.py        # ТАК НЕЛЬЗЯ
```

выдаёт `ImportError: attempted relative import with no known parent package`.
Это нормально: эти файлы — библиотеки, у них нет точки входа.

Правильно:

```bash
python run.py \
    --doc "КТП ПР1 Робототехника.doc" \
    --calendar "календарь часов 2026-2027.xlsx" \
    --weekdays вт,пт \
    --start 01.09.2026 \
    --out output/КТП_готовый.doc
```

Без аргументов запускается интерактивный режим (программа задаст вопросы):

```bash
python run.py
```

Если нужен запуск модуля напрямую, используйте `-m` из корня проекта
(тогда пакет определяется корректно):

```bash
python -m ktpgen.scheduler   # это библиотека, CLI находится в run.py
```

### Параметры

| Флаг | Описание | Пример |
|---|---|---|
| `--doc` | исходный план `.doc` | `"КТП ПР1 Робототехника.doc"` |
| `--calendar` | календарь часов `.xlsx` | `"календарь часов 2026-2027.xlsx"` |
| `--weekdays` | дни недели через запятую | `вт,пт` или `1,4` (пн=0 ... вс=6) |
| `--start` | дата начала занятий | `01.09.2026` |
| `--out` | куда сохранить результат | `output/КТП_готовый.doc` |

## Как это работает

1. `ktpgen/calendar_parser.py` читает `.xlsx`: определяет рабочие даты и
   праздники по **красной** заливке/шрифту ячеек.
2. `ktpgen/doc_model.py` извлекает из текста плана строки занятий с позициями
   дат (`cp_start/cp_end`) внутри потока `WordDocument`.
3. `ktpgen/scheduler.py` подбирает для каждой темы ближайшую подходящую дату:
   указанный день недели, рабочая дата календаря, не раньше `--start`.
4. `ktpgen/doc_writer.py` заменяет даты **побайтово in-place** (длины строк
   совпадают, поэтому FAT/piece table/форматирование не смещаются) и сохраняет
   новый `.doc`.
5. `run.py` делает самопроверку: перечитывает результат и сверяет все даты.

Ожидаемый вывод удачного прогона:

```
Календарь: рабочих дат 251, праздников 15
Найдено занятий: 72
...
Сохранено: output/КТП_готовый.doc
Самопроверка: 72/72 дат совпадают в записанном файле
```

Финальный контроль — открыть `output/КТП_готовый.doc` в Word/LibreOffice.

## Частые ошибки

- `ImportError: attempted relative import...` — запускаете файл из `ktpgen/`;
  запускайте `python run.py` (см. выше).
- `ModuleNotFoundError: openpyxl / olefile` — не активирован venv:
  `source venv/bin/activate && pip install -r requirements.txt`.
- «Не хватило дат для N занятий» — слишком мало выбранных дней недели на
  учебный год; добавьте второй день (например `вт,пт`).
